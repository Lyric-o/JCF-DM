# JCF-DM

**JCF-DM** provides the implementation and experiment entrypoints for
*A Deep Generative Framework for Right-Censored Survival Data with
Distribution-Matching Regularization*.

The project models failure and censoring times with a joint conditional flow
and uses a Soft--Nelson--Aalen Wasserstein regularizer for population-level
distribution matching.

## Reproduced results

| Paper result | Entrypoint | Data |
|---|---|---|
| Table 1: uninformative simulations | `bash scripts/run_table1.sh` | generated by the simulator |
| Table 2: informative simulation | `bash scripts/run_table2.sh` | generated by the simulator |
| Table 3: semi-synthetic clinical covariates | `bash scripts/run_table3.sh` | SUPPORT and Rotterdam--GBSG |
| Table 4: observational benchmarks | `bash scripts/run_table4.sh` | SUPPORT, Rotterdam--GBSG, and restricted SEER |

Reference values from the paper are recorded in
`reference_results/paper_values.md`. Runners write JSON summaries and
per-replication records under `outputs/table*/`.

## Environment

The reported experiments used Linux (RHEL 8), Python 3.11.8, and CPU
execution. Create an isolated environment with:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

No GPU or external service is required. Numerical reductions and early
stopping can produce small cross-platform differences, so Monte Carlo means
should be compared rather than byte-identical output files.

## Quick validation

Run the data-free smoke test from the repository root:

```bash
bash scripts/run_smoke_test.sh
```

This compiles all Python files and performs short training runs to validate
the installation and imports. It is not intended to reproduce a paper value.

## Data

Prepare and validate the public datasets with:

```bash
python scripts/prepare_public_data.py
python scripts/validate_data.py
```

The first command retrieves SUPPORT and Rotterdam--GBSG through `pycox`.
See `data/README.md` for schemas, fingerprints, the `JCFDM_DATA_DIR` override,
and the SEER access restriction. When `seer.csv` is unavailable,
`run_table4.sh` reproduces the two public-data columns only.

Clinical data files are excluded by `.gitignore`; do not commit `seer.csv`.

## Full reproduction

Run one table at a time:

```bash
bash scripts/run_table1.sh
bash scripts/run_table2.sh
bash scripts/run_table3.sh
bash scripts/run_table4.sh
```

Tables 1 and 2 use 30--50 Monte Carlo replications at
`n_train=2048, n_eval=1024`. A serial run of the full synthetic suite takes
approximately 50 CPU-hours; independent methods or replications can be run as
separate jobs. Table 3 uses 10 replications per dataset and dependence
setting. Table 4 uses five stratified 75/25 train/test splits.

Expected cross-environment agreement is approximately 0.02 absolute for KS,
0.10 for W1, and 0.02 for C-index/IBS means. The standard deviations reported
in the paper provide method-specific context. Larger differences usually
indicate a mismatch in data, seeds, sample pooling, or tail conventions.

Appendix sensitivity analyses can be run with:

```bash
python src/ablations/sensitivity_lambda_ic.py \
  --rho 1.0 --family spline --mc_runs 20 --n_train 2048 --n_eval 1024 \
  --K_eps 32 --max_epochs 400 --suffix reproduction
python src/ablations/sensitivity_lambda_S.py \
  --mode S --mc_runs 20 --n_train 2048 --n_eval 1024 \
  --max_epochs 400 --suffix reproduction
```

## Comparison implementations

Several comparisons are study-specific and are labelled accordingly:

- `comparison_lognormal_mixture*.py` implements a DSM-inspired conditional
  LogNormal mixture. `@IC` means it is evaluated unchanged on the informative
  data-generating process; it is not a published method named DSM-IC.
- `comparison_binned_km*.py` implements a WKM-inspired binned conditional-KM
  smoother; it is not a published method named WKM-IC.
- `comparison_deep_lognormal_frank.py` implements the study-specific deep
  LogNormal--Frank comparison rather than the official DCSurvival codebase.

All Table 2 comparison runners use the same Gamma-frailty generator in
`src/synthetic/informative_censoring_impl.py`, the same seed schedule, and 20
model draws per held-out covariate where sampling is required.

## Seeds and evaluation convention

Synthetic main runs use `20260407 + 13*i`. Real-covariate and observational
runners use the schedules encoded in their entrypoints. Table 2 sampling-based
evaluation pools 20 draws per held-out covariate. KM and Cox PH are reported
with fitted-CDF KS only; their W1 values are omitted because the study uses a
common tail-complete W1 convention.
